# Daily, weekly, monthly, and final reports

All reports must be generated from saved session records, not from conversation memory.

## Daily HTML practice sheet

The daily HTML is a practice artifact. It should contain:

1. source metadata and link;
2. annotated source with the learner's raw dictation available;
3. 2-3 highest-priority diagnoses;
4. sentence/meaning-group shadowing chunks with repeat counts;
5. actual expressions from the material;
6. a short completion checklist;
7. the current learning position.

Keep it printable. The clean source and practice instructions matter more than a long essay about errors.

## Weekly report

Create `Reports/weekly/YYYY-Www.md` and a matching CSV. Include:

- date;
- material title and domain;
- learned segment;
- learned_until;
- total error count;
- category counts;
- main weakness;
- expression count;
- pending review items.

## Monthly report

Create `Reports/monthly/YYYY-MM.md` and CSV. Add trend analysis only from records:

- errors by category across sessions;
- repeated patterns;
- materials completed versus in progress;
- expressions reviewed versus newly introduced;
- one or two next-stage priorities.

Do not claim that a lower error count proves improvement unless the materials and conditions are compared.

## Final annotated transcript

Generate only after the learner explicitly confirms that the material is complete. Merge all daily errors while preserving their dates and timestamps. Include a summary table, repeated-error analysis, expression list, and the final source URL.
